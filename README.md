# КРАМ — Telegram Mini App (демоверсія)

Мультикаталог товарів (кросівки, одяг, парфумерія, годинники, аксесуари) у вигляді
Telegram Mini App. Інтерфейс повністю українською, валюта — гривня.

**Статус:** каталог перенесено з постів Telegram-каналу (`src/data/catalog/products.ts`), фото ще не додано. Оформлення замовлення
демонстраційне: дані нікуди не надсилаються, оплата не здійснюється. Серверної частини ще немає.

## Що працює

- Головна: банер, пошук, категорії, «Популярні товари», «Новинки», «Рекомендуємо», «Акції та знижки».
- Каталог: 5 категорій з підкатегоріями, фільтри (ціна, бренд, розмір, колір, об'єм, ремінець, наявність, знижка) і сортування (популярність, новизна, ціна ↑/↓).
- Пошук за назвою, брендом, категорією та підкатегорією; історія запитів.
- Картка товару: галерея, характеристики, вибір розміру / кольору / об'єму / ремінця. Варіанти й поєднання, яких немає, обрати не можна.
- Кошик: зміна кількості та варіанта, видалення з можливістю повернути, автоматичний підрахунок суми.
- Обране.
- Оформлення: перевірка імені, телефону (+380), міста, відділення / поштомата / адреси.
- Профіль: дані користувача Telegram (якщо відкрито в Telegram), контакти, заглушка історії замовлень.
- Кошик, обране, історія пошуку й чернетка форми зберігаються на пристрої (localStorage).
- Інтеграція з Telegram: `ready`, `expand`, кольори шапки, системна кнопка «Назад», вібровідгук.

## Запуск

```bash
npm install
npm run dev            # http://localhost:5173 — розробка
npm run build          # dist/ — для розміщення на хостингу
npm run build:single   # dist-single/index.html — один файл з усіма фото, відкривається без сервера
```

Перевірка основних сценаріїв (29 автоматичних перевірок у мобільному вікні):

```bash
npm run build && npx vite preview --port 4173 &
node scripts/smoke-test.cjs
```

## Розміщення на Railway

Проєкт уже налаштований (`railway.json`): Railway виконує `npm run build`, потім `npm start`
(сервер `serve` віддає `dist/` на порту зі змінної `PORT`).

Через GitHub:
1. Завантажте папку проєкту в репозиторій GitHub (без `node_modules`).
2. Railway → **New Project → Deploy from GitHub repo** → оберіть репозиторій.
3. Сервіс → **Settings → Networking → Generate Domain**. Отримаєте адресу `https://…up.railway.app`.

Без GitHub, через Railway CLI:
```bash
npm i -g @railway/cli
railway login
railway init        # створити проєкт
railway up          # завантажити й зібрати
railway domain      # отримати https-адресу
```

## Бот

`bot.mjs` запускається разом із сайтом, якщо в Railway задано `BOT_TOKEN`.
Бот відповідає на `/start` кнопкою «Відкрити магазин» і сам встановлює кнопку меню.
Адресу магазину бере з домену Railway (`RAILWAY_PUBLIC_DOMAIN`) або зі змінної `WEBAPP_URL`.
Токен використовується лише на сервері й не потрапляє ні в браузер, ні в логи.

## Як підключити до Telegram

1. Розмістіть вміст `dist/` на будь-якому HTTPS-хостингу (Vercel, Netlify, Cloudflare Pages, GitHub Pages тощо). Telegram відкриває Mini App лише за HTTPS.
2. У [@BotFather](https://t.me/BotFather): `/newbot` — створіть бота, потім `/newapp` (або *Bot Settings → Menu Button*) і вкажіть URL сайту.
3. SDK Telegram підвантажується автоматично, коли застосунок відкрито з Telegram.

Для цього потрібні ваш бот і хостинг. Сам я їх не створював і ключів не вигадував.

## Структура

```
src/
  data/
    types.ts            — модель даних (Product, Category, OptionGroup…)
    images.ts           — ключ фото → URL (локальний файл або https://…)
    demo/               — ДЕМО-каталог: categories.ts, products.ts, IMAGE_SOURCES.md
  services/
    catalogService.ts   — звідки береться каталог (зараз демо, далі API)
    orderService.ts     — оформлення замовлення (зараз демо; є місце під API)
    telegram.ts         — обгортка Telegram Mini Apps SDK
  store/                — стан: кошик/обране (shop), каталог, навігація, сповіщення
  lib/                  — чиста логіка: фільтри, ціни варіантів, кошик, валідація, форматування
  components/           — повторно використовувані елементи інтерфейсу
  screens/              — екрани застосунку
  config/shop.ts        — назва, контакти магазину
  styles/app.css        — дизайн-токени та стилі
scripts/
  prepare-images.py     — підготовка фото (квадрат 720px, єдиний фон)
  render-studio.mjs     — рендери флаконів і гаманців для демо
  smoke-test.cjs        — наскрізні перевірки
```

## Заміна каталогу

Інтерфейс не залежить від конкретних товарів. Щоб підставити справжній каталог:

1. Сформуйте список товарів за типом `Product` з `src/data/types.ts` (бренд, назва, ціна,
   стара ціна, фото, опис, характеристики, варіанти з наявністю, теги `new`/`popular`/`recommended`/`sale`).
2. Редагуйте `src/data/catalog/products.ts` (або змініть `loadCatalog` у `catalogService.ts`, щоб брати дані з API / JSON).
3. Фото: покладіть файли в `src/assets/catalog/` і вкажіть у товарі ключ (назва файлу без розширення)
   або одразу повний URL `https://…`.
4. Категорії та підкатегорії без товарів приховуються автоматично.

Відсутні в каталозі дані лишаються порожніми, вигадувати їх не потрібно.

## Що потрібно для наступних етапів

| Функція | Що потрібно від вас |
|---|---|
| Справжні замовлення, історія замовлень | Сервер / БД. `orderService.ts` уже має місце під `VITE_API_URL` |
| Перевірка користувача Telegram | Токен бота на сервері для перевірки підпису `initData` (на клієнті даним не довіряємо) |
| Сповіщення адміністратору | Бот + ID чату адміністратора |
| Нова пошта (пошук відділень, ТТН) | API-ключ Нової пошти |
| Онлайн-оплата | Договір і ключі платіжного сервісу (LiqPay, WayForPay, Monobank тощо) |
| Автоматичне наповнення / ШІ-розпізнавання товарів | Джерела, з яких дозволено брати дані, та ключ обраного ШІ-сервісу |
| Панель адміністратора | Сервер + БД |
